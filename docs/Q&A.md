会议讨论了抖音研发比赛课题的内容、开发要求、所需资源与工具、交付事项，并解答了参会人员的疑问。主要内容包括：

课题内容介绍
课题题目：“实现一个可以端到端交付全栈项目的超级个体”，有最小功能闭环 MVP 模型。
需求链路
流程步骤：从产品用户输入自然语言开始，经澄清 agent 询问 PRD 缺失内容，产出包含技术方案设计和模块拆分等的方案，接着进行 coding，查找已知仓库里的代码，完成代码生成并提交到仓库。
测试要求：为保证代码可用，至少要有 lint 和单测，也可进行端到端测试，最终以提交 PR 结束。
架构分层：分为用户层、后端编排层，用户层可通过 web 页面、客户端或飞书等 IM 工具交互，后端编排列出了相关代码。
练手题目：练手题目有简单分级，分级维度按涉及的上下文依赖和复杂度，前后端结合的需求在扣定环节设计有挑战。
开发要求说明
基础要求：跑通需求链路，基于已知全栈开源仓库开发，最终作业前后端都要落地。
探索方向：探索断点重放功能，使系统具备可观测性，考虑系统自我迭代及需求澄清识别。
开发工具
现存工具：可基于现存 AI 的 CLI 工具（如 OpenCode）、被封装过的 agent 的 SDK 或 langchain langgraph。
选型限制：对 AI 工具和模型选型无严格限制。
开发期望：期望减少人工介入，让产品使用平台完成需求澄清和验证环节，需求验收时用户可自行体验。
资源与工具信息
官方资源：提供 API key，有参考接入文档。
开发工程：建议用 Trae，对火山方舟适配较好，用自己的 AI 工具可能需配置 provider。
交付相关事项
时间要求：以群里同步时间为准。
提交材料：包括源代码、文档说明、技术方案等，技术方案核心观察系统架构图。
演示形式：可在线演示或本地演示，建议提前录屏。
亮点撰写：项目亮点部分可按自身视角撰写，作为评审参考。
问题解答环节
竞赛奖励：第一名有直通终面机会，通过终面可获实销分。
技术问题：文档会发放，后端开发语言、Agent 开发语言不做限制，沙盒调用第三方无限制。
需求相关：需求基于博客系统新增功能，Skill 是沉淀超级个体的载体，新增需求形式多样，复杂度不设上限。
抄袭判定：参考开源内容不算抄袭，理解系统并能在答辩回答问题即可。
沙盒环境：基于沙盒仓库做功能迭代，实现层面隔离维度无限制。
评测加分：通过 SWE bench 评测可作为加分项。
