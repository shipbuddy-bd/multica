## 1. 一句话现状

**端到端跑通了：** `POST /api/pipelines/trigger` → Orchestrator 创建 Clarify 子 issue + edge + 任务 → Daemon 用 pipeline-aware prompt 跑 doubao → 任务完成 → Orchestrator 自动推进到下一阶段。已用真实 Conduit 仓库验证 SHI-10 完成 `clarify → plan` 的自动转换。

**还没跑完整链路：** plan → implement → validate → handoff 这三段尚未在真实环境观察过，特别是 **implement 阶段是否真能提交代码到 Conduit 分支** 还没验证。

### 4.2 数据库观察（替换为你的 root issue UUID）

```sql
-- pipeline 树
SELECT i.number, i.title, i.status
FROM issue i
WHERE i.parent_issue_id='<root>' OR i.id='<root>'
ORDER BY i.number;

-- pipeline 边
SELECT source.number AS from_n, target.number AS to_n, e.edge_type, e.metadata::text
FROM pipeline_edge e
JOIN issue source ON source.id=e.source_issue_id
JOIN issue target ON target.id=e.target_issue_id
WHERE e.workspace_id='<ws-uuid>'
ORDER BY e.created_at;

-- 任务流水
SELECT id, issue_id, status, started_at, completed_at, error
FROM agent_task_queue
WHERE runtime_id='<rt-uuid>'
ORDER BY created_at DESC LIMIT 10;
```
